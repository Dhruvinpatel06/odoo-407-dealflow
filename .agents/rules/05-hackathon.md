# DealFlow360 Hackathon Rule

- Optimize for a demonstrably working backend.
- Prefer simple deterministic implementations where requirements leave formulas unspecified.
- Do not spend hackathon time on speculative production infrastructure.
- Avoid premature abstractions.
- Keep scope aligned with the finalized documents.
- Build seed/demo data that supports acceptance flows.
- Every completed phase should leave the repository runnable.
- If time is limited, finish quotation -> risk -> approval -> fulfillment -> billing before optional polish.
